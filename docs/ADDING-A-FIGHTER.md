# Как добавить персонажа

Десять способностей уже реализованы и проверены (`src/sim/abilities.test.ts`,
демонстрация — `out/demo/ten-abilities.mp4`). Не хватает только фотографий:
персонаж в этом формате **это фотография**, и её кладёшь ты.

## Что должно быть на фотографии

Требования не про вкус, а про то, что делает `pnpm cutout` и как рисуется кадр.

1. **Белый студийный фон.** Вырезка — заливка от края кадра по белому (порог
   236). Серый, градиент, интерьер, тень на полу — фон не снимется, и на арене
   будет прямоугольник.
2. **Человек целиком в кадре, обрезанный по пояс или по бедро.** Замерено: у
   референса ширина к росту 0.57-0.61, у нас 0.63-0.84. По грудь — слишком
   широко, в полный рост — слишком узко.
3. **Разрешение от 700px по короткой стороне.** Боец рисуется примерно на 414px
   при кадре 1080.
4. **Лицо видно, поза читаемая.** Персонаж — это гэг: профессия даёт силуэт и
   предмет в руках. Прошлый ростер из двенадцати профессий не работал именно
   потому, что смотреть было не на что.
5. **Один человек.** Не двое, не человек с обрезанным вторым за плечом.

## Лицензия — это твоё решение и твой риск

У стоковых лицензий обычно есть пункт про то, что модель нельзя показывать в
невыгодном виде, а здесь её бьют, бросают через арену и она проигрывает. Это
известно и записано в CLAUDE.md.

**Свободные фотографии тут не помогут, и я проверял.** CC0-стоки (StockSnap,
Openverse, Wikimedia) дают лайфстайл в интерьере, а не студийные вырезки — из
240 результатов по «man» ни одного на белом. И главное: CC0 покрывает авторское
право, а не право человека на своё изображение. Для монетизируемого канала
покупная сток-лицензия с релизом модели — единственный спокойный путь.

## Дальше — три команды

```bash
# 1. положить файл
cp ~/photos/plumber.jpg assets/fighters/source/plumber-guy.jpg

# 2. вырезать фон и посчитать контур
pnpm cutout

# 3. дописать в src/content/roster.ts:
#    {
#      id: "plumber",
#      faction: "left",
#      name: "Plumber Guy",
#      spriteId: "plumber-guy",     // = имя файла без расширения
#      maxHp: 1000,                 // у всех одинаковый, см. CLAUDE.md
#      attackSpeed: 0.85,
#      critChance: 0.18,
#      critMult: 1.5,
#      meleeShare: 1.0,             // насколько он опасен в столкновении
#      abilities: [{ type: "wall_slam", cooldown: 6, power: 0, hitShare: 2.0 }],
#      fieldScale: 1.0,             // решится автоматически на шаге 4
#    }

# 4. пересчитать урон и выровнять пары
pnpm solve 3
pnpm balance
```

`pnpm solve` решает `fieldScale` всего ростера сразу, как неподвижную точку —
бисекция на четверых уже не работает, а на четырнадцати тем более: у каждого
винрейт зависит от всех остальных.

## Чего ждать при десяти новых

- **91 пара вместо шести.** `pnpm solve` и `pnpm balance` будут идти минутами,
  а не секундами.
- **Баланс придётся решать заново целиком**, не по одному бойцу.
- **Стиль живёт в `meleeShare` и `hitShare`, а не в `attack`.** `attack` решает
  калибратор, и любое значение, вписанное туда руками, он сотрёт на следующем
  прогоне.
- **Ровный овералл не значит ровные пары.** Смотреть надо на матрицу
  `pnpm balance`, а не на средние.

## Десять способностей, которые ждут

| тип | что делает |
| --- | --- |
| `switcheroo` | меняет двоих местами |
| `magnet_pull` | тянет противника к себе |
| `spin_cycle` | кружит вокруг противника |
| `overclock` | ускоряется, каждый контакт — крит |
| `dead_weight` | встаёт намертво, противник отскакивает |
| `wall_slam` | сам в стену, противника — от стены |
| `siphon` | снятое здоровье приходит кастеру |
| `countdown` | тяжёлый удар через 2.5 секунды |
| `riposte` | возвращает полученный контактный урон |
| `slipstream` | проходит сквозь противника |

Плюс шесть уже занятых: `magnetic_north`, `thrown_out`, `haymaker`,
`glasses_throw`, `four_eyes`, `nobody_moves`.

Если способности нужен предмет — фото на белом в `assets/props/source/` под
именем из `ABILITY_PROPS`, дальше тот же `pnpm cutout`. Без предмета ни одна из
десяти не ломается: все они делают что-то видимое сами.
